ToTaskFlow 단일 EC2 GitHub Actions 설정

등록 위치:
GitHub 저장소 > Settings > Secrets and variables > Actions

구조:
단일 EC2
  ├─ Nginx: 정적 파일, API 프록시, HTTPS
  ├─ Spring Boot: 애플리케이션
  ├─ MySQL 8.4: 데이터베이스
  ├─ Docker volume: DB와 업로드 파일
  └─ Certbot: Let's Encrypt 인증서 발급·갱신

GitHub Actions는 서버 인프라를 생성하거나 변경하지 않는다.
이미 준비된 EC2에 애플리케이션만 배포한다.


============================================================
1. Actions Variables — 필수 6개
============================================================

PUBLIC_SITE_URL
https://totaskflow.com

DOMAIN_NAME
totaskflow.com

TLS_EMAIL
Let's Encrypt 만료·보안 알림을 받을 운영 이메일

EC2_HOST
EC2 고정 공인 IP

EC2_USER
서버 로그인 사용자 이름
예: ec2-user 또는 ubuntu

EC2_SSH_PORT
22


============================================================
2. Actions Secrets — 필수 15개
============================================================

EC2_SSH_PRIVATE_KEY
EC2 생성 시 선택한 Key pair의 전체 PEM 개인키

EC2_SSH_KNOWN_HOSTS
아래 명령 결과를 서버 지문과 대조한 뒤 전체 출력 등록
ssh-keyscan -p 22 <EC2 고정 공인 IP>

MYSQL_APP_PASSWORD
Spring Boot 전용 MySQL 사용자 비밀번호

MYSQL_ROOT_PASSWORD
MySQL root 비밀번호

JWT_SECRET
생성 명령:
openssl rand -base64 64

OAUTH2_GOOGLE_CLIENT_ID
Google Cloud Console OAuth 2.0 Client ID

OAUTH2_GOOGLE_CLIENT_SECRET
Google Cloud Console OAuth 2.0 Client Secret

MAIL_HOST
운영 SMTP 호스트

MAIL_PORT
운영 SMTP 포트

MAIL_USERNAME
운영 SMTP 사용자 이름

MAIL_PASSWORD
운영 SMTP 비밀번호 또는 App Password

MAIL_FROM
검증된 운영 발신 주소

TOSS_CLIENT_KEY
토스페이먼츠 테스트 클라이언트 키
반드시 test_ck_ 또는 test_gck_로 시작

TOSS_SECRET_KEY
토스페이먼츠 테스트 시크릿 키
반드시 test_sk_ 또는 test_gsk_로 시작

PAYMENT_ENCRYPTION_KEY_BASE64
저장된 테스트 빌링키 암호화용 32-byte 키
생성 명령:
openssl rand -base64 32


============================================================
3. Actions Secrets — 나중에 등록 1개
============================================================

OPENAI_API_KEY
OpenAI 리포트 구현이 완성되고 로컬 테스트를 통과한 뒤 등록
현재 비어 있어도 배포와 서비스 실행에 영향 없음

실제 키 값은 코드, 문서, 커밋, Actions 로그에 기록하지 않는다.


============================================================
4. EC2 필수 조건
============================================================

- 고정 공인 IP 사용
- 서버 방화벽 인바운드
  - TCP 22: 본인 고정 IP/32만 허용
  - TCP 80: 0.0.0.0/0
  - TCP 443: 0.0.0.0/0
- 3306, 8081, 19091, 19092는 외부에 열지 않음
- Docker Engine과 Docker Compose plugin 설치
- systemd 사용 가능
- 배포 사용자가 비밀번호 입력 없이 sudo docker와 sudo systemctl을 실행할 수 있어야 함
  GitHub Actions SSH 세션에서는 sudo 비밀번호를 대화형으로 입력할 수 없음

영구 데이터:

- mysql-data: MySQL 데이터
- uploads: 사용자 업로드 파일
- letsencrypt: TLS 인증서

EC2 또는 Docker volume을 삭제하면 데이터가 사라질 수 있다.
운영 전 DB와 uploads의 정기 백업·복원 테스트가 반드시 필요하다.


============================================================
5. 가비아 DNS
============================================================

가비아 네임서버와 DNS 관리 기능을 그대로 사용한다.

@    A        <EC2 고정 공인 IP>
www  CNAME    totaskflow.com.

TTL은 600초 권장.
DNS 전파가 완료된 뒤 최초 배포를 실행한다.


============================================================
6. 서버 직접 HTTPS
============================================================

최초 배포:

1. Nginx가 HTTP와 인증서 검증 경로를 연다.
2. Certbot이 서버에서 Let's Encrypt 인증서를 발급한다.
3. Nginx가 HTTPS 설정으로 재시작한다.
4. HTTP는 HTTPS로 리디렉션된다.

systemd timer가 매일 인증서 갱신을 확인하고 Nginx를 reload한다.

Google OAuth 승인된 리디렉션 URI:

https://totaskflow.com/login/oauth2/code/google


============================================================
7. CI/CD 동작
============================================================

main 브랜치 CI 성공
  ↓
backend/web 이미지를 GHCR에 빌드
  ↓
sha-<commit SHA> 태그로 버전 관리
  ↓
SSH로 단일 EC2의 /opt/totaskflow에 설정 업로드
  ↓
MySQL → Spring Boot → Nginx 순서로 상태 확인
  ↓
Certbot 인증서 발급 또는 갱신
  ↓
https://totaskflow.com 공개 health check

토스페이먼츠는 테스트 키와 TOSS_TEST_MODE=true로만 실행한다.
SUBSCRIPTION_LIVE_BILLING_ENABLED=false는 고정한다.
