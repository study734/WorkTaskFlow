# 2026-07-30 개발 로그

## 작업 단계

- 단계: AI 주간 리포트 품질 향상
- 상태: 디자인 통일성 복귀 완료. 내용 재설계는 계획 승인, 착수 전
- 범위: 리포트 reader 시각 계약, 서술 prompt

## 경과

리포트 화면을 편집형(명조·고정폭·지면·출처 레일)으로 재설계했으나 앱의 카드 UI와 이질적이라는
제품 판단에 따라 되돌렸다. 시각 언어는 `--app-purple` 계열 카드 UI로 복귀했고, 재설계 과정에서
발견한 실제 결함 네 가지만 남겼다.

## 완료한 작업

### 디자인 복귀

`styles.css`의 리포트 구역과 `AiReportContent`를 커밋 969cafb 상태로 되돌린 뒤, 다음 네 가지만
다시 적용했다. 순수 미감 변경은 남기지 않았다.

| 수정 | 결함 |
|---|---|
| `word-break: keep-all` | 한국어가 단어 중간에서 줄바꿈됐다 |
| 증감 방향 표시 | 지연 업무 증가가 중립 색으로 표시돼 악화로 읽히지 않았다 |
| 우선 행동 1열 | `P1→P2→P3` 순위를 2열 그리드가 뭉갰다 |
| 위험 안내문 섹션 1회 | 같은 문장을 서버 위험 항목 수만큼 반복했다 |

증감 방향은 부호가 아니라 방향으로 판정한다. 완료 업무 감소와 지연 업무 증가는 부호가 반대지만
둘 다 `악화`다. 앱의 성공·위험 색(`#1f6d46`/`#b3263e`)은 2형 색각에서 구분이 어려우므로 색 단독에
의존하지 않도록 부호와 `개선`/`악화` 문구를 항상 함께 표시한다.

### 서술 prompt v6

- summary가 headline을 바꿔 말하지 못하게 하고 지배적 신호 지목과 그 뒤의 진단을 요구했다.
- 위험에 예상 영향뿐 아니라 그 위험을 확인하거나 배제할 관찰을 함께 쓰도록 했다.
- 행동의 확인 시점을 evidence placeholder이거나 명시적 상대 구간으로 강제했다.
- `SCHEMA_VERSION`은 `v4` 유지. 저장 마이그레이션이 없고 기존 frozen revision과 확정본은 그대로다.

### 수동 테스트 환경 기동

`scripts/ai-report-manual-test.ps1`의 백엔드 대기 시간 60초가 콜드 스타트에 부족했다. Flyway 26개
마이그레이션만 27초, 전체 기동 37.3초가 걸려 스크립트가 부팅 중인 백엔드를 스스로 종료시켰다.
공유 스크립트를 수정하지 않고 동일한 환경변수로 직접 기동했다. 대기 시간을 120초로 올리는 편이 맞다.

## 확인한 설계 결함 (미해결)

내용 품질의 원인을 추적한 결과다. 계획은 승인됐고 구현은 착수 전이다.

- AI에 업무 제목·설명·보류사유·상태변경사유·댓글이 전혀 전달되지 않는다. 상태 전이만 서술할 수
  있어 어떤 prompt로도 구체성에 상한이 걸린다.
- 일별 시계열, `averageCompletionHours`, 일부 상태 수, 목표별 지연 수는 모델에 전달되지만
  evidence key가 없어 인용이 불가능하다. 개인정보 비용 없이 열 수 있는 여지다.
- 팀원별 수치는 `NarrativeContract` 내부에서 삭제 후 전송된다.
- 교차 주차 맥락이 없어 재생성해도 동일 prompt가 전달된다.
- 근거 약 12개로 서술 슬롯 18개를 채워 중복이 구조적으로 발생한다.
- 연결 업무가 0건인 주간 목표는 리포트에 나타나지 않는다.

## 검증

- 프런트 빌드 통과: `npm run build` (CSS 112.58 kB → 100.56 kB)
- AI 리포트 Chrome E2E 15건 통과: `npx playwright test ai-weekly-report`
  기존 13건은 무수정 통과. 증감 방향과 안내문 비중복 검증 2건을 추가했다.
- 백엔드 report 테스트 35건 통과:
  `JAVA_HOME=<jdk21> .\mvnw.cmd -Dtest=NarrativeContractTest,OpenAiResponsesNarrativeAdapterTest,WeeklyReportModuleTest,WeeklyReportLifecycleTest test`
- 실행 중인 앱에서 증감 방향 표시를 실데이터로 확인했다. 지연 `+6`이 `악화`로 표시된다.

## 미검증

- 실제 OpenAI 키를 사용한 prompt v6의 서술 품질·거절·timeout 동작은 검증하지 않았다.
  수동 하네스의 Fake AI는 입력과 무관한 고정 문자열을 반환하므로 prompt 출력의 증거가 되지 않는다.
- 서버 생성 PDF 템플릿은 이번 범위에서 제외했다.

## 환경

- 기본 `JAVA_HOME`이 Temurin 17이라 `mvnw`가 release 21을 컴파일하지 못한다. JDK 21을 명시해 실행했다.

## 보안

- OpenAI API key, access token, fixture 비밀번호를 로그나 저장소에 기록하지 않았다.
- provider 입력의 익명화된 집계·별칭 계약을 바꾸지 않았다. prompt 변경은 편집 지침만 건드렸다.
